# Mininet Design Decisions

Decision register for the independent Mininet integration work. Evidence references: spec requirement numbers from `docs/MININET_SPECIFICATION_AUDIT.md` (R-x.y) and component rows from `docs/MININET_REPOSITORY_AUDIT.md`.

Status: **DECIDED** (directly supported by the specification or by Prajin-owned code), **ASSUMPTION** (reasonable and reversible; needs confirmation), **BLOCKED** (cannot be completed without an external input).

Confirmation column: who must eventually confirm (P = Praveen, J = Jayadev, T = Tejaswi, — = nobody).

| D-06 | Readiness delays ρi are derived exactly as in the simulator: `SeedSequence(network_round_seed(seed, r)).spawn(6)[2]`, then `integers(0, ⌊0.1·D⌋ + 1)` ns per client in id order, sent as `rho_us = ⌊ρ/1000⌋`. Implemented in `fedgrant/mininet/round_loop.py:readiness_delays_us`. | R-6.4, R-11.1, R-11.2 (pairing) | Mininet runs and their M-sim twins share readiness draws, as §14 requires | Fresh RNG per process (breaks pairing) | `gateway_proc.py` still sends ρ = 0; the one-line adoption is proposed in D-11 | DECIDED | T (adopt in `gateway_proc`) |
| D-07 | B1 and B2 clients do not send READY; they start at ρi after ROUND_START. | R-3.1, R-3.2; ambiguity A3-1 | §10 describes B1/B2 starting "at readiness" with no READY; adding READY would add bytes counted in protocol overhead | Send READY for η accounting | B1/B2 η needs client-side energies (D-09) | ASSUMPTION | T, J |
| D-08 | Baseline control channel: the gateway's UDP socket on port 9000 sends `ROUND_START(mode, absolute deadline_ns, K, L, rho_us)` to clients on port 9001 and sends `ROUND_END(bitmap)` at D for every baseline. B1 DATA uses TCP port 9100, B2/B3 DATA use UDP 9000. | R-1.5, R-2.13, R-3.4, R-3.5 | Error feedback is held constant across baselines and needs ROUND_END; the ROUND_START mode field exists for this | Out-of-band delivery results (not available across Mininet hosts) | New processes only; class defaults (9101/9102) unchanged | DECIDED | — |
| D-09 | B1/B2 η in Mininet: clients record each round's sorted energies and send order (`client_<i>_rounds.jsonl`); the gateway records delivered block indices per client and round (`gateway_rounds.jsonl`); `fedgrant.mininet.baseline_metrics.round_eta` joins them after the run. (7) | Protocol-neutral; uses the definition of η exactly | Gateway-side estimate from payloads (cannot see undelivered energy) | Runner/raw-metrics integration of the join is pending | ASSUMPTION | T |
| D-10 | Network-only client updates come from the real bank: `energies = bank.energies_for_run_round(seed, r)[i]`; the payload is `synthetic_update(energies, seed = SeedSequence([seed, r − 1, 2, i]).generate_state(1)[0])` (the seed agreed in `docs/MININET_INTEGRATION_CONTRACT.md` §3), with block j given the j-th stored energy. The seed fixes only the direction of each block's values; block energies do not depend on it. `fedgrant/mininet/value_profiles.py` loads the bank with `load_value_bank` (which verifies provenance) and raises if it is missing. There is no synthetic-bank fallback; fixture banks are used only in tests via explicit injection. | R-5.1, R-5.2; ambiguity A5-2; `profile_update.synthetic_update`; seed convention of `client_proc.py` and `run_baselines._client_delta` | Values match the bank profile, as in the simulator | Use `profile_bank` (synthetic, not allowed for M1) | `client_proc.py` adoption proposed (T) | ASSUMPTION (payload construction) | J |
| D-11 | Shared round loop: `fedgrant/mininet/round_loop.py` provides `RoundSchedule` (Tc = 1.0 s, D, late drain), `readiness_delays_us`, and the async `run_round_loop(...)` driving: compute window → start hook (ROUND_START) → deadline hook (ROUND_END) → late-drain window → finalize hook. The baseline gateway consumes it. `gateway_proc.py` is not modified; adopting the helper there is a proposed change for Tejaswi. | R-6.1, R-6.5; repository audit §4 | Keeps lifecycle shared and protocol-specific code separate; telemetry samplers are separate processes and continue through the drain | Edit `gateway_proc.py` now (Tejaswi-owned) | None for existing runs | DECIDED (helper) / ASSUMPTION (adoption) | T |
