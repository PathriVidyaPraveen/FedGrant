# Specification change log

Section 19 of the specification requires an amendment line here, approved by
all four members, for any change to a binding parameter.

| Date | Parameter | Old value | New value | Reason | Status |
|---|---|---|---|---|---|

| 2026-11-13 | Client uplink loss scope (Section 7, client egress `ci-eth0`) | `netem ... loss gemodel p r 100% 0%` applies to every frame a client sends, including READY | READY frames (UDP to the gateway port, FedGrant type 2) bypass the Gilbert–Elliott loss and keep the access delay δi; DATA and every other client frame keep the configured GE loss, delay and TBF unchanged | Section 6 delivers READY on a delay-only path in the simulator, while Section 7 applied loss to it; at N = 20, 13–16% of READYs were lost, a client without READY is excluded for the whole round and η cannot be computed, which biases M1 against its M-sim twin. Conditions: the filter matches only READY; verify all READYs arrive and DATA still sees the configured GE loss; rerun every M1 run made before the change | APPROVED by all four (Tejaswi, Praveen, Jayadev, Prajin; 2026-11-13). No M1 run had been made before the change. Approved together with the readiness timer origin row below |
| 2026-11-13 | Readiness timer origin (Sections 2.1, 6, 7) | Simulator: READY arrives ρi + δi + 5 ms after the round start (ROUND_START reaches clients instantly); Mininet: client waits ρi after receiving ROUND_START, which itself takes δi + 5 ms, and after encoding its update | ρi starts when the client receives ROUND_START (Section 2.1 wording). Simulator: READY arrival = ROUND_START downlink (δi + 5 ms) + ρi + READY uplink (δi + 5 ms); Mininet client: receive timestamp captured before update encoding, READY scheduled with `call_at(received_at + ρi)`. Seeded ρi stream unchanged | On Fedora (N = 20, L2) Mininet READYs arrived δi + 5 ms (15–45 ms) later than the simulator model, plus a median 5.5 ms of encoding before the timer (`results/summary/testbed_ready_timing.csv`), biasing M1 vs M-sim calibration. Owners: Prajin (`net/udp_client.py` timer), Jayadev (`sim/run_net.py` formula); Tejaswi reruns the Fedora timing measurement. Simulator results made before the change are rerun | APPROVED by all four (Tejaswi, Jayadev, Prajin, Praveen; 2026-11-13), together with the READY loss exemption above (kept as separate rows at Jayadev's and Prajin's request). Consequences: simulator results and M1 results made with the old timing are rerun; the ML dataset (`data/mldata`, simulator-generated) is regenerated by Jayadev and P-GRU/P-MLP retrained by Praveen; models pushed before that retraining are for integration testing only.
